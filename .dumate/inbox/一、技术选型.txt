

一、技术选型

Flutter 3.x + Dart 3 + Material 3，Android

- 状态管理：Riverpod（比 Provider 更安全，编译期检查依赖）
- 路由：go_router（声明式，深链接友好）
- 网络：dio + retrofit（接口自动生成，少写样板）
- 模型：freezed + json_serializable（不可变模型 + 自动 fromJson）
- 本地缓存：Hive（轻量、无需 SQL，缓存赛历和积分足够）
- 图片：cached_network_image（磁盘缓存 + 占位图 + 淡入）
- 时间：intl（时区/日期格式化）
- 图表（可选）：fl_chart，做积分趋势曲线时才需要

Flutter 相对 RN 的最大优势在这里：底部导航、卡片、转场动画都是 Material 现成的，不用自己画，做“简约好看”成本最低。

二、架构分层

建议 Feature-first + Clean Architecture 三层，两个功能各一个 feature 目录，互不依赖：

presentation（UI）  →  domain（实体 + 用例 + 仓库接口）  →  data（API/缓存实现仓库）

- domain 只放纯 Dart，不 import Flutter，方便以后换 UI 或做桌面版
- data 里一个 RaceRepository、一个 StandingsRepository，内部组合“远程 API + 本地缓存”
- presentation 用 AsyncNotifier 暴露 AsyncValue<...>，UI 直接 switch 出 loading / error / data 三态

关键设计：缓存过期策略写在 Repository 里，不写在 UI。赛历缓存 24 小时，积分缓存 5 分钟，打开 App 先显缓存再后台刷新（stale-while-revalidate），这样弱网也秒开。

四、数据与接口

用 Jolpica-F1（免费、无需 key、Ergast 兼容），两个端点就够：

- 赛历：GET https://api.jolpi.ca/ergast/f1/2026.json
- 车队积分：GET https://api.jolpi.ca/ergast/f1/2026/constructorStandings.json

“下一场比赛”不用额外接口：拿全季赛历，用本地时间过滤 race.date >= now 取第一条。当前实测就是 第 21 站 拉斯维加斯，11 月 22 日，之后是卡塔尔 11/29、阿布扎比 12/6 收官。

积分榜现状（截至第 20 站）：Mercedes 652 > Ferrari 510 > Red Bull 415 > McLaren 398 > RB 114 > Alpine 69 > Haas 31 > Audi 28 > Williams 12 > Aston 7 > Cadillac 0。

补充两点工程上的注意：
- 接口有数据滞后（原定 24 站，巴林、沙特已取消，接口现在返回 23 条），所以前端要能容错站点数量变化，别硬编码 24。
- 加一个 etag/Last-Modified 条件请求，省流量，对弱网友好。

五、页面结构

底部两个 Tab（Material 3 NavigationBar）：

1. 赛历 Tab
   - 顶部「下一场比赛」大卡片：赛道城市 + 日期 + 倒计时（天/时/分）+ 该站赛道名；卡片背景用对应国家的低饱和渐变
   - 下方整季赛历列表：月份分组、已赛/未完赛用不同文字色、冲刺赛用小徽标标注
2. 积分 Tab
   - 车队积分榜：每行 = 队色竖条 + 队名 + 积分 + 名次变化箭头
   - 行左侧放赛车缩略图（车图裁切），右侧大数字积分；点某队进详情页（车图全幅 + 两名车手头像）

交互细节建议：Tab 切换用 AnimatedSwitcher 淡入，下拉刷新用 RefreshIndicator，积分变化做数字滚动动画——成本很低但“高级感”全在这。

六、视觉规范（这是你想要的“好看简约”）

- 底色 #F3F3F3（Windows 11 的窗口底），卡片纯白，圆角 12px，阴影 0 1 3 rgba(0,0,0,.06)（很淡，不要 Material 默认那种重阴影）
- 强调色 #0067C0（Windows 蓝）或 #2196F3（Material 蓝），二选一，别混用
- 字体：Segoe UI Variable（Windows）→ 移动端回退 Inter / Roboto；数字用 tabular figures，积分对齐才整齐
- 字号层级只有 4 级：32（大数字）/ 20（标题）/ 15（正文）/ 12（辅助），克制是简约的核心
- 深色模式用 ColorScheme.dark 自动反色，底色 #1F1F1F、卡片 #2B2B2B
- 细节：分割线用 1px #E5E5E5，不要用卡片堆叠阴影；每屏最多一个“重色块”

七、图片策略（很重要）

官方车图是 2600×572 的横幅，直接放列表会非常浪费流量。这些 URL 是 Cloudinary 变换地址，把 w_2600 改成 w_600（列表）/ w_1200（详情）即可拿到对应尺寸，画质不变：

.../c_lfill,w_600/q_auto/v1740000001/common/f1/2026/ferrari/2026ferraricarleft.jpg

配合 cached_network_image 的 memCacheWidth 限制解码尺寸，能省 70% 内存。车图统一 BoxFit.contain（白底，别裁切），列表里加 color: Colors.white 底板，视觉才不会碎。

八、开发节奏（建议）

- 第 1 天：项目骨架 + 主题 + 底部导航 + 假数据跑通两个页面
- 第 2–3 天：Jolpica 接入、模型、Repository + Hive 缓存、三态处理
- 第 4 天：图片映射表接入、卡片刻度打磨、倒计时逻辑
- 第 5 天：下拉刷新、错误页、深色模式、真机适配（刘海/安全区）
